Based on my previous post on [Rapid iteration with Agents](/posts/2026-01-24-rapid-iteration-with-agents), I've been iterating through some project setups that meet the requirements of resilience, speed, isolation, and reproducibility.

After a weekend of tinkering, I'm settling on a pretty nifty structure.

## Architectural Assumptions

This framework assumes the following stack (but obviously is reproducible with different stacks, the principles probably translate just fine):

- bun.sh
- next.js
- prisma.js
- postgreSQL

## The Requirements in Practice

The workflow I'm aiming for is as follows:
- It should do everything locally (this is my bias, always),
- It should allow me to work on parallel features in different git worktrees (and therefore branches),
- It should allow each branch should get its own database to iterate against
- It should allow for integration testing locally against the database
- It should do all of the above with _speed_

## The Tools

I've gone through a few iterations of this over the years, and usually this has involved multiple docker containers. I'd create a container for my test-db, and run a full migration against it then provide some seed data. Because this was slow, I'd stick to using a single dev-db for all my branches (which historically wouldn't include worktrees at all, but LLM's have introduced me to their wonders).

Today, I have a simpler, faster structure, but it involves a little more set up (the best practice tax!). The secret is using postgreSQL `TEMPLATES`, and a few small scripts to manage my set up.
